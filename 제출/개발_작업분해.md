## 2. 병렬화의 전제 — 계약 먼저

**오늘(9/1) 안에 아래 JSON 스키마부터 확정**하고, 각자 그 스키마의 목업으로 작업합니다.
A는 `public/mock/*.json`을 그대로 읽어 화면을 만들고, B는 같은 모양을 반환하는 서버를 만들면, 마지막에 fetch 주소만 바꾸면 붙습니다.

### 2-1. API 계약 (5개)

```
POST /api/classify        1층 · 자유서술 → 유형 분류
POST /api/evidence        2층 · 유형+은행 → 체크리스트 + 은행 요구서류 + 발급 요청문
POST /api/analyze         거래내역·대화 → 사실관계 + 불일치 + 금액 정합성
POST /api/draft           3층 · 소명서 3종 생성 (스트리밍)
GET  /api/banks           은행 20곳 목록 (정적)
```

**POST /api/classify**

  "answers": { "q1": "bank" } }
// 응답
{ "track": "bank",              // bank | police | alert | civil | unknown

### 2-2. 계약 고정 규칙

- **필드명은 오늘 확정하고 그 뒤로는 바꾸지 않음.** 바꿔야 하면 3명 동시 합의
- 프론트는 **응답이 비어 있어도(null·빈 배열) 화면이 깨지지 않게** 방어
- 서버는 실패해도 **HTTP 200 + `{ error }`** 로 응답 (프론트 분기 단순화)

## 3. 기술 결정 사항

| 항목 | 결정 | 이유 |
|---|---|---|
| 프론트 | 현행 유지 (React 19 + Vite + Tailwind v4) | 이미 6화면이 있음. 갈아엎을 시간 없음 |
| 서버 | Node + Express **또는** 배포처의 서버리스 함수 | API 키를 브라우저에 노출하면 안 됨. **필수** |
| LLM | Anthropic SDK (`@anthropic-ai/sdk`), 모델 `claude-opus-5` | 분류·생성 모두 동일 모델. 모델 두 개 쓰면 캐시가 분리되어 손해 |
| 1층 출력 | **structured outputs** (`output_config.format`) | 분류 결과를 JSON 스키마로 강제해야 프론트가 안전하게 분기함 |
| 3층 출력 | **스트리밍** (`client.messages.stream` → `.finalMessage()`) | 소명서는 길어서 논스트리밍은 타임아웃 위험 |
| 프롬프트 캐싱 | 시스템 프롬프트 + 코퍼스 근거를 **앞쪽에 고정** 배치 | 프리픽스 일치 캐시. 변동값(사용자 입력)은 반드시 뒤에 |
| RAG | **임베딩 인덱스 대신 태그 매칭 + 사전 큐레이션 JSON** | 6일 안에 벡터DB까지 하면 못 끝냄. 유형·은행이 이미 라벨이라 매칭으로 충분 |
| 캡처 이미지 판독 | **채택 (Claude 멀티모달 입력)** | 별도 OCR 벤더를 두지 않고, 분류·분석 호출에 이미지 블록을 함께 실어 보냄. 추출값은 사용자 확인 후 사용 |
| 분류 호출 비용 | `output_config.effort` 를 **낮게** 설정 | 분류는 짧은 판별 작업임. 생성(3층)만 높은 effort 로 둠 |

### 3-1. 이미지 입력 (B·A 공통)

캡처를 그대로 보내면 토큰이 크게 늘어납니다. **이미지는 입력 토큰으로 과금**됩니다.

```ts
// 분류 호출에 캡처를 얹는다 — 별도 엔드포인트 없음
messages: [{ role: "user", content: [
  { type: "image", source: { type: "base64", media_type: "image/png", data: b64 } },
  { type: "text", text: 사용자서술 },
]}]
```

- **base64 문자열에 개행이 있으면 안 됩니다.**
- 업로드 직후 **긴 변 기준 약 1,500px로 리사이즈**한 뒤 전송하십시오. 문자 판독에는 충분하고 토큰은 크게 줄어듭니다.
- 캡처는 **비캐시 구간**입니다. 매 요청 달라지므로 프롬프트 앞쪽에 두면 캐시가 통째로 깨집니다.
- 여러 장을 한 번에 받으면 비용이 배로 늘어납니다. **1회 1장**으로 제한하고, 추가 자료는 다음 단계에서 받으십시오.

### 3-2. 캐싱 배치 (B 담당자용)

```
[캐시 구간]  시스템 프롬프트(고정) → 법령 원문 → 판례 스니펫 → 은행 데이터
[비캐시]     사용자 서술문 · 문진 답변 · 업로드 자료
```
`usage.cache_read_input_tokens`가 0이면 앞쪽에 변동값이 섞인 것이니 즉시 점검.
