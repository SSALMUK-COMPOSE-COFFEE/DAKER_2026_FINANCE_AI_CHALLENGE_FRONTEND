# 「풀림」 서비스 플로우 — 재설계

작성 2026-08-30 · 기준 **유형지도 12개 장의 조사 결론** + 현재 `src/` 구현 상태

이 문서는 세 가지로 씁니다. **첨부1 기획서 5번(활용 데이터·생성형 AI)의 근거**, **첨부2 기능명세서 3·5번의 원고**, 그리고 **남은 개발의 작업 지시서**입니다.

앞선 판(코드 기준으로 정리한 것)을 버리고 다시 썼습니다. **코드가 유형지도의 결론을 거의 반영하지 못하고 있어서, 코드를 기준으로 삼으면 조사 결과가 통째로 빠지기 때문**입니다.

- ✅ **구현됨** — 지금 코드에 있고 동작합니다
- 🔧 **수정 필요** — 구현은 됐는데 조사 결과와 어긋납니다
- ⬜ **미구현** — 아직 없습니다

## 1부 · 왜 다시 설계하는가

### 문진이 유형지도와 어긋나 있습니다

| 유형지도 원문 8문항 | 현재 코드 | 상태 | **새 문진에서 (1-C)** |
|---|---|---|---|
| **1. 지금 어떤 상황이신가요?** (은행 연락 / 경찰 연락 / 징후만 / 소송서류) | 코드 Q1 "어떤 상황에서 **계좌가 정지되었나요**" | **어긋남** | **Q1** — 정지를 전제하지 않는 문구로 교체 |
| 2. 그 돈이 왜 들어왔다고 생각하셨나요? | — | 누락 | **Q3** — 「어떤 거래로 받으신 건가요」로 고쳐 씀 |
| **3. 문제가 된 입금 건을 알려주던가요?** (날짜·시각·금액·입금자명) | — | **누락** | **Q2** — 원문보다 앞으로 당김 |
| **4. 들어온 금액이 약속한 금액과 같았나요?** | — | **누락** | **Q6** |
| 5. 상대가 돈을 돌려달라고 했나요? | — | 누락 | **Q6 후속** |
| 6. 무엇을 넘기셨나요? | 코드 Q3 (플랫폼만 물음) | 부분 | **Q4** — 목적물 8종으로 확장 |
| 7. 거래 방식과 상대 | 코드 Q4 인도 방식 | 부분 | **Q5**(전달 방식) + **Q7**(입금자명) |
| 8. 도박·환치기·접근매체·대리인출·대리송금 | 코드 Q2 (접근매체만) | 부분 | **Q8** — 5종으로 확장 |

**세 벌의 번호가 한 표에 있습니다.** 왼쪽 열은 유형지도 원문 번호, 가운데는 **현재 코드**의 문항 번호, 오른쪽이 **새로 쓸 문진**의 번호입니다. 원문 8문항이 하나도 버려지지 않고 전부 살아 있으며, **순서만 두 군데 바꿨습니다** — 원문 3번(입금 건 특정)을 2번으로 당기고, 원문 2번(돈의 명목)을 3번으로 내렸습니다. 뒤따르는 문항들이 "그 돈"을 지칭하려면 어느 입금인지가 먼저 정해져야 하기 때문입니다.

### 이 어긋남이 만드는 세 가지 구멍

**첫째, 아직 안 묶인 사람을 못 받습니다.** 코드 Q1이 "계좌가 정지되었다"를 전제하기 때문입니다. 그런데 코퍼스에는 **정지 직전 경고 단계가 26건** 있습니다 — 더치트에 계좌가 등록되고 예금주명이 "사기계좌확인요망"인 1원이 들어온 상태입니다.

유형지도 07장의 결론이 이랬습니다. *"대면 직거래 증거는 사후에 복구가 불가능하다. 서비스의 가치가 소명서 작성이 아니라 '지금 당장 이것부터 저장하세요'라는 선제 안내에 있는 구간이다."* **개입할 수 있는 유일한 시점인데 문진이 그 사람들을 받지 않습니다.**

**둘째, 경찰 길로 가야 할 사람에게 소명서를 만들어 줍니다.** 유형지도 04장의 갈림길 1에서 빠지면 계좌는 안 묶이고 경찰서에서 부릅니다. 게임재화 심층분석 3건이 전부 그랬습니다. 그 사람들에게 필요한 것은 이의제기신청서가 아니라 **진술서**입니다.

**셋째, 무엇을 팔았는지를 안 묻습니다.** 유형지도 05장 전체가 *"무엇을 팔았느냐가 증거를 정한다"*인데, 코드는 플랫폼(당근·번개·중고나라)만 묻습니다. **플랫폼은 증거를 정하지 않습니다.**

| 팔았던 것 | 증거를 어디서 받나 | 현재 반영 |
|---|---|---|
| 게임 재화·계정 | 게임사 고객센터 거래 로그 | ✗ |
| 상품권·기프티콘 | 발행사 사용이력 조회 | ✗ |
| 암호화폐 | 블록체인 전송 기록 (가장 강력) | ✗ |
| 금·귀금속·외화 | **구청 관리 대로변 CCTV 열람신청** | ✗ |
| 팬덤 굿즈 | 배대지 주소 · 외국인 입금대행 흔적 | ✗ |
| 실물 중고물품 | 택배 송장 (대면이면 사실상 없음) | 부분 |

### 그리고 객관식 문진만으로는 애초에 부족합니다

유형지도가 **19개 유형**을 발굴했습니다. 객관식 몇 문항으로 19개를 가를 수 없습니다.

더 근본적인 문제는 **당사자가 자기 유형을 모른다**는 것입니다. "3자사기"라는 말도 나중에 알게 됩니다. 실제 커뮤니티 글 제목이 이렇습니다.

> *"당근거래 후 지급정지 당했는데 조언 좀 부탁드리겠습니다 ㅠㅠㅠ"*
> *"이거 3자사기 가능성이 있나"*
> *"3자 사기에 연루된것 같은데 아.. 골치아프네요"*

객관식은 "가장 가까운 것"을 고르게 하는데, **경계에 있는 사람이 잘못 고르면 그 뒤가 전부 틀어집니다.**

## 2부 · AI를 세 층으로 나눕니다

핵심 설계입니다. AI가 한 덩어리로 "알아서 잘해주는" 구조가 아니라, **하는 일이 다른 세 층으로 나누고 각 층의 책임을 분명히** 합니다.

```
┌─ 1층 · 분류 ────────────────────────────────────────┐
│  자유 서술 + 최소 객관식                              │
│      ↓ LLM                                          │
│  트랙 · 구조 · 목적물 · 법 제7조 몇 호로 다툴지        │
│  확신도가 낮은 축만 되묻는다                          │
└─────────────────────────────────────────────────────┘
                        ↓
┌─ 2층 · 검색 (RAG) ──────────────────────────────────┐
│  자체 구축 코퍼스에서 근거를 가져온다                  │
│   ① 내 은행이 실제로 요구하는 서류                    │
│   ② 이 유형에서 법원이 인정한 증거                    │
│   ③ 관련 법 조문과 판례                              │
│   ④ 증거 발급처와 요청 방법                          │
└─────────────────────────────────────────────────────┘
                        ↓
┌─ 3층 · 생성 ────────────────────────────────────────┐
│  1층 사실관계 + 2층 근거 + 사용자 증거                │
│      ↓ LLM                                          │
│  이의제기 사유란 · 경위서 · 증거 인덱스                │
│  ★ 2층이 가져온 근거 안에서만 인용한다                │
└─────────────────────────────────────────────────────┘
```

### 왜 RAG가 장식이 아니라 필연인가

**우리가 이미 모아 둔 자료가 정확히 RAG 소스입니다.**

| 소스 | 규모 | 무엇에 답하나 |
|---|---|---|
| **은행 이의제기 요구서류 조사** | 금융회사 20곳 | **"내 은행은 무엇을 요구하나"** |
| 판결문 원문 + 판례 | 18건 + 33건 | "이런 경우 법원이 무엇을 인정했나" |
| 금감원 보도자료 + 첨부 PDF | 49건 + 32건 | 공통 소명자료 기준, 소액 간소화 요건 |
| 법령 원문 | 통신사기피해환급법·시행령 | 제7조 1항 2호·3호, 제8조 2항 2호 단서 |
| 정리된 피해사례 | 233건 | "나와 비슷한 사람은 어떻게 했나" |
| 당사자 게시글 | 222건 | 유형별 실제 수법과 대응 |

**첫 줄이 이 서비스의 결정적 기능입니다.** 금융회사 20곳 중 이의제기 요구서류를 사용자에게 보여줄 수 있는 곳이 **5곳(25%)**이고, **유형별로 안내하는 곳은 0곳**입니다. 5곳은 안내문에 서류를 열거한 3곳(카카오·씨티·전북)과, 안내문은 없지만 배포 중인 법정서식에 첨부서류가 적혀 있는 2곳(하나·케이뱅크)입니다. 그런데 저희는 그 20곳을 직접 조사해서 갖고 있습니다.

사용자가 자기 은행을 고르면 **그 은행이 실제로 요구하는 것**을 알려주는 기능 — 국내에 존재하지 않고, **우리 데이터가 있어야만 만들 수 있습니다.**

### 환각을 구조로 막습니다

3층은 **2층이 가져온 근거 안에서만** 인용하게 합니다. 생성된 모든 문장에 출처 번호를 붙이고, **근거가 없는 문장은 만들지 않습니다.**

이게 판례와도 맞아떨어집니다. 조사에서 확인한 것이 **"거래 당시에 만들어진 문서만 인정되고 사후에 쓴 진술서는 배척된다"**였습니다. 그러니 **AI가 지어내지 못하게 막는 구조가 곧 제품의 강점**입니다. 잘 지어내는 것이 아니라, 있는 것만 정확히 배열하는 것이 목표입니다.

### 안 쓰기로 한 것

**계좌 관계망을 그래프로 분석하는 판정형 모델(GNN 등)은 이번 범위에서 씁니다.** 이유는 두 가지입니다.

첫째, **국내 실사례에 계좌 단위 자금흐름 데이터가 거의 없습니다.** 수집한 사례에서 재이체 여부·자금 체류시간·입금 건수가 사실상 전부 "미상"이었습니다. 검증할 수 없는 모델은 넣지 않습니다.

둘째, **"판정하는 프레임"을 만들지 않는다**는 원칙과 충돌합니다.

관계망은 판정의 도구가 아니라 **정지가 어떻게 번졌는지를 설명하는 화면**으로만 남깁니다.

## 3부 · 재설계한 흐름

화면은 6단계 그대로입니다. 코드 구조를 크게 바꾸지 않으면서 내용을 유형지도에 맞춥니다.

```
0. 서비스 소개    1. 상황 진단          2. 증거 준비
   소개·동의   →   자유서술→분류→확인  →  맞춤 체크리스트
                        ↓
                  ┌─────┴─────┬──────────┬──────────┐
                은행 길    경찰 길    경보 단계   범위 밖
                (계속)   (진술서 안내) (지금 저장) (종료)

3. AI 분석        4. 소명서 초안        5. 제출 지원
   사실 구조화  →   근거 인용 생성   →   은행별 안내
```

---

## 0단계 · 서비스 소개와 동의 ✅ 🔧

접속하면 안내 모달이 먼저 뜹니다. 세 가지를 분명히 밝힙니다.

1. **풀림은 법률 대리인이 아닙니다.**
2. **결과를 보장하지 않습니다.** 최종 판단은 은행과 금융감독원이 합니다.
3. **자료를 저장하지 않습니다.** 작성이 끝나면 지웁니다.

### 🔧 한 줄 추가해야 합니다

> **저희가 돕는 것은 지급정지 이의제기이지 형사 무죄가 아닙니다.**

같은 행위에 사기방조는 무죄, 전자금융거래법 위반은 유죄가 동시에 나온 판결이 있습니다(서울중앙지법 2020노66). **"속았다"가 인정돼도 형사책임이 0이 되지는 않습니다.** 계좌가 묶인 사람은 지푸라기라도 잡는 심정이라 이 구분을 먼저 해줘야 합니다.

## 1단계 · 상황 진단 ⬜ 전면 재설계

### 1-A. 먼저 자유롭게 적게 합니다 ⬜

> **무슨 일이 있었는지 편하게 적어주세요.**
> 법률 용어를 쓰실 필요 없습니다. 언제 무엇을 팔았고, 어떤 연락을 받았는지 아는 대로만 적어주세요.
>
> *(건너뛰고 질문에 바로 답하셔도 됩니다.)*

**이 칸이 있는 이유**가 있습니다. 커뮤니티 글을 보면 사람들은 이미 자기 상황을 길게 씁니다. 그 서술 안에 우리가 물어볼 것의 절반이 이미 들어 있습니다. **객관식으로 조각내서 다시 묻는 것보다, 쓴 것을 읽고 모자란 것만 되묻는 편이 빠르고 정확합니다.**

건너뛸 수 있게 합니다. 글쓰기가 부담인 사람도 있습니다.

### 1-B. LLM이 읽고 분류합니다 ⬜

**1층 AI가 하는 일입니다.**

| 판별하는 축 | 값 |
|---|---|
| **트랙** | 은행 길 / 경찰 길 / 경보 단계 / 민사 / 판단 불가 |
| **구조** | 물건 넘김 / 물건 없이 계좌만 거쳐감 / 통장묶기 / 환전·대리송금 |
| **목적물** | 실물중고 · 상품권 · 게임재화 · 팬덤굿즈 · 금외화 · 암호화폐 · 용역 · 없음 |
| **다툴 조항** | 법 제7조 1항 1호 / 2호 / 3호 |
| **범위 밖 신호** | 접근매체 제공 · 도박 환전 · 환치기 · 대리 인출 |

**확신도가 낮은 축만 되묻습니다.** 자유 서술에서 이미 답이 나온 질문은 건너뛰고, "이렇게 이해했는데 맞나요?" 하고 확인만 받습니다.

### 1-C. 확인 문항 — 유형지도 8문항 골격 ⬜ 🔧

자유 서술에서 채워지지 않은 것만 묻습니다. 아무것도 안 적었다면 8개를 다 묻습니다.

---

#### Q1. 지금 어떤 연락을 받으셨나요? ⬜ **← 트랙이 여기서 갈립니다**

| 선택지 | 가는 곳 |
|---|---|
| 은행에서 계좌가 정지됐다고 연락이 왔습니다 | **은행 길** — 계속 진행 |
| 경찰에서 조사받으러 오라고 연락이 왔습니다 | **경찰 길** — 다른 안내 |
| 아직 연락은 없는데 이상한 게 보입니다 | **경보 단계** — 지금 당장 저장할 것 안내 |
| 소송 서류나 내용증명이 왔습니다 | **민사** — 별도 안내 |
| 잘 모르겠습니다 | 되묻기 |

**세 번째 선택지를 고르면 이렇게 되묻습니다** — 더치트에 내 계좌가 등록됐다 / 1원이나 100원처럼 이상한 소액이 들어왔다 / 예금주명이 이상한 문구였다 / 상대가 연락을 끊었다.

**왜 이 질문이 첫 번째인가.** 유형지도 04장의 핵심 발견입니다. 계좌가 묶이느냐는 *내가 무엇을 팔았는지*가 아니라 *나에게 돈을 보낸 사람이 무슨 말에 속았는지*로 갈리는데, **당사자는 그걸 알 방법이 없습니다.** 사기범이 반대편에서 무슨 말을 했는지 모르기 때문입니다.

그래서 **당사자가 볼 수 있는 유일한 신호가 "어디서 연락이 왔나"**입니다. 은행이면 계좌가 묶인 것이고, 경찰이면 안 묶였을 가능성이 큽니다.

#### Q2. 어떤 입금 때문인지 알고 계신가요? ⬜ **← 여기서 사건이 특정됩니다**

> 방금 받으신 연락에서 **어느 입금이 문제인지** 알려주던가요?

| 선택지 | 다음 |
|---|---|
| 은행(또는 수사관)이 문제가 된 입금 건을 알려줬습니다 | 알려준 내용을 그대로 옮겨 적습니다 |
| 알려주지는 않았는데 **짚이는 거래가 있습니다** | 그 거래를 기준으로 아는 만큼 적습니다 |
| 알려주지도 않았고 **짚이는 거래도 없습니다** | **"먼저 확인하세요" 액션 카드** + 유형 신호로 기록 |

입력칸은 **날짜 · 시각 · 금액 · 입금자명** 넷이고, **아는 것만 적어도 넘어갑니다.** 빈칸은 나중에 채우도록 자리를 남겨둡니다.

**왜 이 질문이 Q1 바로 다음이어야 하는가.** 세 가지입니다.

**첫째, 이 답이 없으면 뒤따르는 질문들이 지시 대상을 잃습니다.** 바로 다음 문항이 "**그 돈**은 어떤 거래로 받으신 건가요"인데, **"그 돈"이 어느 입금인지가 아직 정해지지 않았습니다.** 계좌에 입금이 여러 건 있으면 답할 수가 없고, 앞선 판에서 이 문항이 뒤(Q7)에 있었던 탓에 정확히 그 상태였습니다.

**둘째, 유형지도 원문도 이 질문을 세 번째에 두었습니다** — *"은행이나 경찰이 문제가 된 입금 건을 알려줬나요?(날짜·시각·금액·입금자명) … **이후 모든 증거 수집의 기준점**"*. 앞선 판이 이걸 맨 뒤로 밀어놓은 것이 원문 이탈이었습니다.

**셋째, "모르겠다"는 답 자체가 즉시 산출물을 만듭니다.** 원문의 근거가 디시인사이드 사례입니다 — *"수사관한테 꼬치꼬치 캐물어서 몇일 몇시 거래내역이냐고 물어서 시간 받아냄. 넥슨 고객센터에 해당일자 거래내역 뽑아달라고 요청해서 프린트."* **문제 입금의 일시를 특정해야 비로소 증거 수집이 시작되는데, 원문 지적대로 "대부분의 명의인은 이 발상 자체를 못 합니다."** 그래서 세 번째를 고르면 그 자리에서 **은행 콜센터·담당 수사관에게 물을 문장 템플릿**을 카드로 내보냅니다. 문진은 멈추지 않습니다.

**그리고 세 번째 선택지는 그 자체가 유형 신호입니다.** 계좌는 묶였는데 짚이는 거래가 하나도 없다면 **거래 없이 계좌만 이용된 유형**(계좌도용 T9 · 통장묶기 T10·T11)일 가능성이 큽니다. 다음 문항의 "거래한 적이 없는데 모르는 사람이 보냈습니다"로 그대로 이어집니다.

**금액 세 가지(거래금액·공고금액·계좌잔액) 대조는 여기서 받지 않습니다.** 공고금액은 채권소멸절차 개시 공고를 받은 사람만 알 수 있어서, 문진 초반에 물으면 대다수가 빈칸으로 지나갑니다. **은행 길로 판정된 뒤 조건부 문항에서** 받습니다.

#### Q3. 그 돈은 어떤 거래로 받으신 건가요? ⬜ **← 구조가 여기서 갈립니다**

> 은행이 문제 삼은 그 입금이 원래 무슨 돈이었는지부터 확인하겠습니다. 사실 그대로 고르시면 됩니다.

| 선택지 | 이 답이 뜻하는 것 |
|---|---|
| 물건이나 서비스를 팔고 받은 대금입니다 | 전형 3자사기 계열 — 계속 진행 |
| 일한 대가입니다 (급여·용역비·수수료) | 금감원 "용역 대가" 표준 소명자료 경로 |
| 가족이나 아는 사람이 보내준 돈입니다 | 거래 자체가 없는 유형 — 계좌 정상성으로 다툼 |
| 거래한 적이 없는데 모르는 사람이 보냈습니다 | **계좌도용·통장묶기 의심** — 절대 손대지 말 것 안내 |
| 환전받은 돈입니다 (게임·토토·해외송금) | **범위 밖 신호** — Q8 리스크 게이트로 직행 |
| 부탁을 받고 제가 다시 다른 곳으로 보내준 돈입니다 | **즉시 경고 + 전문가 연결** — 운반책 혐의 구간 |
| 잘 모르겠습니다 | 되묻기 |

**Q1·Q2를 답했으면 이건 이미 아는 것 아닌가.** 아닙니다. **어디서 연락이 왔는지도, 어느 입금이 문제인지도 유형을 하나도 좁히지 못합니다.** "은행에서 계좌가 정지됐다는 연락을 받았다"는 T1부터 T15까지 전부에서 똑같이 나오기 때문입니다. 당근에서 노트북을 판 사람, 사설토토 환전을 받은 사람, 남편이 준 생활비를 받은 사람이 **Q1에서 글자 하나 다르지 않게 답합니다.** Q1은 *어느 절차로 갈지*(마감 시계·제출처·서류 종류), Q2는 *어느 입금이 대상인지*(사건 특정), Q3은 *돈이 왜 들어왔는지*(유형)를 정합니다. 세 축이 직교합니다.

**Q3은 혼자서 네 갈래를 그 자리에서 확정합니다.** 환전(T12·T13) · 대리송금(T14) · 가족지인(T15) · 모르는 돈(T9~T11). 유형지도 코퍼스에서 **T12가 13건으로 최대 군집**이고, 이 사람들이 전부 Q1의 "은행 연락"으로 들어옵니다. **Q3이 없으면 이들에게 소명서를 만들어 주게 되고, 그 소명서가 도박죄 자수 문서가 됩니다.**

Q8이 최종 방벽이지만, Q3에서 "환전받은 돈"을 고르면 **Q8로 즉시 건너뛰어** 나머지 문항을 헛되이 답하기 전에 세웁니다. Q3과 Q8이 겹쳐 보이는 것은 중복이 아니라 **조기 게이트 + 최종 백스톱**의 이중화입니다.

가장 또렷한 사례가 「남편이 준 생활비 200만원, 알고보니 '도박자금'」과 「양아버지 '월급'인 줄 알았는데 내 통장으로 1000만원」입니다. 두 사람 모두 Q1은 "은행에서 정지 연락"이고, **Q3에서 "가족이 보내준 돈"이라고 답하는 순간에야** 필요한 증거가 택배 송장에서 *생활비로 실제 썼다는 지출 흐름*으로 통째로 바뀝니다.

**왜 "왜 들어왔다고 생각하셨나요"가 아닌가.** 앞선 판은 유형지도 원문 문장을 그대로 옮겼는데, 그 문장은 *당시의 판단*을 묻습니다. 물건을 팔고 대금을 받은 대다수 이용자에게는 답이 하나뿐이고, **묻는 쪽이 이미 의심하고 있다는 인상**을 줍니다. Q1에서 "은행에서 연락이 왔다"고 답한 사람에게는 더 그렇습니다.

같은 축(돈이 들어온 명목)을 **사실만 묻는 형태**로 바꿨습니다. 명의인이 실제로 알 수 있는 것만 묻는다는 유형지도의 설계 원칙에도 이쪽이 맞습니다.

**선택지를 원문대로 되살렸습니다.** 앞선 판이 6지선다를 4개로 줄이면서 *급여·용역비* · *가족·지인 송금* · *내가 다시 송금해 준 돈* 세 갈래가 빠졌는데, 마지막 것은 유형지도에서 **즉시 경고 분기**로 지정된 항목이라 누락되면 안 됩니다.

#### Q4. 무엇을 넘기셨나요? ⬜ **← 증거 발급처가 여기서 정해집니다**

| 선택지 | 이 답이 여는 증거 경로 |
|---|---|
| 실물 중고물품 (휴대폰·노트북·자전거 등) | 택배 송장 / 대면이면 이동 기록·CCTV |
| 상품권·기프티콘 | **발행사 사용이력 조회** · 핀번호 전송 화면 · 편의점 CCTV |
| 게임 재화·계정 | **게임사 고객센터 거래 로그** · 거래소 인수인계 기록 |
| 팬덤 굿즈 (앨범·포토카드·티켓) | 택배 송장 · 오픈채팅 · **배대지 주소 기록** |
| 금·귀금속·외화 현금 | **구청 관리 대로변 CCTV 열람신청** · 매입 영수증 |
| 암호화폐 | **블록체인 전송 기록** (가장 강력) |
| 용역·서비스 | 계약서 · 작업물 · 정산 내역 |
| 아무것도 넘기지 않았습니다 | 계좌 정상성으로 다툼 |

**유형지도 05장의 표가 여기서 그대로 쓰입니다.** 그리고 07장의 결론 — *"발급 요청문을 대신 써 주는 기능이 가장 값싸고 효과가 크다"* — 가 이 문항 없이는 성립하지 않습니다.

#### Q5. 어떻게 전달하셨나요? ⬜ (부분 ✅)

택배 발송 / 직접 만나서 / 온라인으로 전송(핀번호·계정·아이템) / 아직 전달하지 않음

**직접 만나서**를 고르면 여기서 바로 경고합니다.

> **가게 CCTV는 보통 30일이면 지워집니다.** 지금 바로 거래 장소와 시각을 적어두시고, 대화 기록·이동 기록(지도 앱, 교통카드)부터 저장하세요.

#### Q6. 들어온 금액이 약속한 금액과 같았나요? ⬜ **← 가장 강력한 단일 신호**

| 선택지 | 무엇을 뜻하나 |
|---|---|
| 같았습니다 | 물건 넘김 구조 |
| **더 들어왔습니다** | **"물건 없이 계좌만 거쳐감" 구조 의심 → 즉시 경고** |
| 덜 들어왔습니다 | 부분 입금 · 추가 확인 |
| 기억나지 않습니다 | 거래내역에서 확인하도록 안내 |

**"더 들어왔습니다"를 고르면 그 자리에서 멈추고 경고합니다.**

> **차액을 돌려달라는 연락을 받으셨다면, 절대 돌려주지 마세요.**
> 지금 돌려주시면 자금세탁의 중간 통로가 되어, 본인이 형사 책임을 지게 될 수 있습니다.
> 돈은 그대로 두시고 **은행을 통해서만** 반환 절차를 밟으세요. 은행 기록이 남아야 합니다.

실제 사례에서 *"외국인이라 환율 오류가 났다"*며 대행인 계좌로 환불을 요구하는 수법이 반복 확인됐습니다. 문화상품권 13.5만원을 넣고 14만원을 환불받았다가 **5천원 초과 하나로 이의제기가 통째로 거부**된 사례도 있습니다.

**그리고 반드시 이어서 물어야 합니다 — 돌려달라고 하던가요?** ⬜ 유형지도 원문 5번이 이 질문이고, 앞선 판에서 통째로 빠져 있었습니다.

| 선택지 | 판정과 즉시 출력 |
|---|---|
| 돌려달라고 했는데 **아직 안 보냈습니다** | ✅ **가장 좋은 상태** — 반환 요구 대응 스크립트 + 은행 착오송금 반환절차 안내 |
| 돌려달라고 해서 **이미 보냈습니다** | 🚨 **가장 나쁜 상태** — 자금 전달책 혐의로 지위가 바뀝니다. 즉시 경찰 신고 + 전문가 연결 |
| **처음 보낸 사람이 아닌 다른 계좌**로 보내달라고 했습니다 | 🚨 3자 구조 확정 신호 |
| 협박(경찰에 신고하겠다 등)이 있었습니다 | 협박 대응 스크립트 + 대화 보존 안내 |
| 그런 요구는 없었습니다 | 계속 진행 |

**"이미 보냈다"를 놓치면 안 되는 이유가 있습니다.** 이 답이 나온 사람은 **더 이상 무고한 수취인이 아니라 자금을 이동시킨 사람**이고, 방어선 자체가 다릅니다. 소명서를 만들어 주는 것이 도움이 아니라 해가 되는 구간이라 Q8과 같은 급으로 다뤄야 합니다.

**다만 출력은 "돌려주지 마세요"가 아니라 "은행 절차로만 돌려주세요"여야 합니다.** 진짜 착오송금도 실재하고 수취인에게는 반환 의무가 있습니다. 유형지도가 인용한 원문도 정확히 이 선을 지킵니다 — *"진짜 실수로 입금한 경우라면 은행 가서 입금반환신청하면 은행 통해서 돈 돌려받을 수 있으니까 그렇게 안내해줘."*

#### Q7. 입금자 이름이 대화 상대와 같았나요? ✅

같았음 / 달랐음 / 기억나지 않음

**"달랐음"이 3자사기의 구조적 증거입니다.** 판매자는 사기범과 대화하고 돈은 전혀 모르는 피해자에게서 옵니다. 그래서 **대화 기록에 입금자 이름이 한 번도 안 나옵니다.** 이 '없음'이 오히려 무고함을 보여줍니다.

여기서 "같았음"을 골라도 안심시키지 않습니다. 실제 사례에 *"구매자와 입금자의 이름이 일치하는 걸 확인하고 물건을 보냈습니다"*인데도 당한 경우가 있습니다. 사기범이 피해자에게 **"판매자 이름으로 보내라"**고 시키기 때문입니다.

|---|---|
| 통장·카드·OTP·비밀번호를 남에게 넘김 ✅ | **영구 제외.** 전자금융거래법상 피의자 |
| 도박·토토 사이트 환전 ⬜ | **자기부죄** — 소명하려면 도박 사실을 스스로 진술해야 함 |
| 환치기·개인 간 외환 거래 ⬜ | **자기부죄** — 외국환거래법 위반 소지 |
| 남의 돈을 대신 인출하거나 송금해 줌 ⬜ | 자기부죄 · 운반책 혐의 |
| 해당 없음 | 계속 진행 |

**이 분기가 왜 필요한가.** 조사에서 확인된 반려 사유의 상당수가 서류 부족이 아니라 **원인이 된 거래 자체의 적법성 문제**였습니다 — "해외 포커사이트 게임머니", "외국환거래법 위반". **소명을 하려다 다른 위법을 스스로 밝히게 되는 구간**이라, AI가 문장을 만들어 주면 안 됩니다.

#### 조건부 추가 문항 ⬜

- **은행 길이면** — 계좌가 정지된 날짜 ✅ / **채권소멸절차 개시 공고 통지를 받으셨나요** ⬜ / 어느 은행들이 막혔나요 ⬜
- **모두에게** — 과거에 지급정지를 당한 적이 있나요 ⬜ *(있으면 소액 간소화 트랙이 별도 검토 없이 자동 불수용되므로 미리 알려야 합니다)*
- **모두에게** — 이미 취하신 조치 ✅

**은행 길이면 금액 세 가지를 따로 받습니다** — 조사에서 나온 것 중 가장 실무적인 발견입니다.

| 입력칸 | 무엇인가 |
|---|---|
| **거래금액** | 내가 물건을 팔고 받기로 한 돈 (Q2에서 이미 받았으면 자동으로 채웁니다) |
| **공고금액** | 채권소멸절차 개시 공고에 적힌 금액 |
| **계좌잔액** | 정지된 계좌에 남아 있는 돈 |

**이 셋을 따로 받아야 하는 이유**가 있습니다. 환급청구의 상한은 "내가 받은 돈"이 아니라 **"공고되어 소멸된 채권액"**입니다. 어떤 사건에서 거래금액 21,040,000원 / 소멸채권 20,000,000원인데 21,090,000원을 청구했다가 **초과분이 기각되고 소송비용 1/10을 부담**했습니다.

그리고 다른 사건에서는 지급정지액·이전 피해금·공고액 세 숫자가 서로 어긋났고 법원이 **"차이가 나게 된 경위를 명확히 밝힌 바는 없다"**고 지적했습니다. **기관이 준 숫자가 서로 안 맞는 경우가 실제로 있습니다.** 세 값을 대조해 어긋나면 화면에 표시하고, 청구액에 자동으로 상한을 겁니다.

### 2-B. 완결성 게이지 ✅

필수 항목을 얼마나 채웠는지를 보여줍니다.

**왜 필요한가.** 2026년 5월 표준화로 충분한 자료를 내면 **5영업일 안에 심사 결과**를 받는 길이 생겼는데, 자료가 모자라면 보완 요청이 반복되고 **보완 기한을 놓치면 이의제기가 자동으로 불수용 처리**됩니다. 제출 전에 상태를 보여줘야 합니다.

### 🔧 고칠 것 — 틀린 서류를 안내하고 있습니다

현재 코드가 **"재직증명서 또는 고용계약서 (택1)"**이라고 안내하는데 **틀렸습니다.**

금감원 원문 표는 **건강보험자격득실확인서 · 재직증명서** 중 택일입니다. 고용계약서는 택일 대상이 아닙니다.

그리고 **건강보험자격득실확인서를 기본값으로 제시해야 합니다.** 회사에 알리지 않고 본인이 온라인에서 즉시 뗄 수 있기 때문입니다. **계좌가 묶인 사실을 회사에 알리고 싶지 않은 사람에게 이건 큰 차이입니다.**

### ⬜ 추가할 것 — "소득 증명"이 아니라 "생계 연관성 증명"

조사에서 찾은 활로입니다. 소액 간소화 트랙의 요건 중 **"입금액을 제외한 입출금 내역이 생계 등과 연관된 것이 명확한 경우"**라는 문장에는 **소득이나 재직에 대한 언급이 전혀 없습니다.**

그래서 C(계좌 정상성)를 이렇게 넓힙니다.

- 통신비·전기·가스 자동이체 / 카드대금 결제 / 교통카드 충전
- 부모의 정기 생활비 송금 / 등록금·기숙사비

**이런 장기 반복 패턴은 대포통장에는 절대 없습니다.** 오히려 소득 증빙보다 강합니다. 그리고 **학생과 무직자도 소명할 수 있게 됩니다** — 지금 체크리스트는 재직자만 상정해서 우리 핵심 이용자층(10~30대)의 상당수가 빠집니다.

보조 수단도 전부 온라인 즉시 발급입니다 — 어카운트인포 자동이체 등록정보, 건강보험자격득실확인서, 국민연금 가입증명, 재학증명서.

**한계도 같이 밝힙니다** — "소액"의 기준 금액이 비공개라 진입을 보장할 수 없고, 결과는 **일부지급정지 전환**(입금액을 뺀 잔액만 해제)이지 입금액 자체의 해제가 아닙니다.

| 위 결과 + 거래내역 CSV | **입금자명과 대화 상대의 불일치 감지** | 불일치 지적 문단 |
| 거래금액·공고금액·계좌잔액 | **세 값 대조, 어긋나면 표시** | 금액 정합성 표 |
| 거래내역 전체 | 계좌 개설연수·자동이체 반복성·급여 주기성 산출 | 생활계좌 근거 목록 |
| 전부 | 증거를 A/B/C/D에 배치 | 증거 인덱스 |

**이미지 OCR은 GCP Vision으로 붙입니다.** 지급정지 문자를 받은 자리에서 휴대폰으로 쓰는 서비스라, 대화도 거래내역도 **손에 있는 건 캡처 이미지**입니다. 텍스트 붙여넣기와 CSV 업로드는 그대로 두고 OCR을 입력 경로로 하나 더 얹습니다. 다만 **OCR은 입력 수단일 뿐이고, 판단은 텍스트화된 결과로만 합니다** — 비전 모델에 사실관계 추출까지 맡기지 않습니다.

### 점수 하나로 요약하지 않습니다

계좌 정상성은 **근거를 나열**합니다. 계좌를 만든 지 몇 년 됐는지, 자동이체가 몇 달째 반복되는지, 문제가 된 거래가 평소 패턴에서 얼마나 벗어나는지.

**"판정하지 않는다"는 원칙 때문이기도 하고, 은행 심사자가 읽어야 하는 것이 점수가 아니라 근거이기 때문**입니다.

## 4단계 · 소명서 초안 ✅(화면) ⬜(생성)

### 출력 형식이 이미 정해져 있습니다

**법정 서식에서 사람이 직접 쓰는 칸은 「이의제기 사유」 단 하나**입니다. 그 칸을 어떻게 채우는지에 대한 **국내 유일의 공개 가이드**가 카카오뱅크 작성예시이고, 세 항목입니다.

1. **입금 금액과 시간**
2. **입금 경위**
3. **권원 주장과 증빙**

**생성기 출력이 정확히 이 형태여야 합니다.** 다른 형식으로 예쁘게 뽑아봐야 사용자가 다시 옮겨 적어야 합니다.

### 만드는 문서 세 가지

| 문서 | 내용 |
|---|---|
| **이의제기신청서 사유란** | 위 3항목. 문장마다 근거 증거 번호 |
| **경위서** | 자기소개·계좌 이력 → 판매 경위 → 거래 진행(입금자명 불일치 해명) → 정지 인지와 대응 → 가담 부인 → 요청과 증거목록 |
| **증거 인덱스** | 모든 주장에 [증거 n] 상호참조 |

### ⬜ 3층이 지켜야 할 규칙

**2층이 가져온 근거 안에서만 인용합니다.** 생성된 문장마다 출처를 답니다.

| 문장 종류 | 출처 |
|---|---|
| 사실 진술 | [증거 n] — 사용자가 올린 자료 |
| 법적 근거 | [법 제7조 제1항 제2호] — 법령 원문 |
| 설득 논거 | [대법원 2024다216187] — 판례 코퍼스 |
| 절차 요구 | [금감원 2026-04-30 보도자료] |

**근거가 없는 문장은 만들지 않습니다.** 화면에서도 인용된 사실과 서술 문장을 시각적으로 구분해, 사용자가 사실과 다른 부분을 직접 고칠 수 있게 합니다.

### 인용할 판례를 RAG가 골라옵니다 ⬜

예를 들어 금·귀금속을 대면으로 판 사람이면 이 판례가 붙습니다.

> 중고거래로 순금 목걸이를 팔고 제3자 명의로 보이스피싱 피해금을 받은 판매자에 대해 — **악의·중과실이 없으면 법률상 원인이 있고, 그 증명책임은 피해자에게 있다**
> — 대법원 2024. 6. 27. 선고 2024다216187

**민사 부당이득 법리라 은행 심사에 구속력은 없습니다.** 그래서 "설득 논거"로 표시해 넣고, 그렇게 안내합니다.

### 제출 전 고지 ✅

거짓 이의제기는 **3년 이하 징역 또는 3천만원 이하 벌금**(법 제16조)임을 고지하고 동의를 받습니다.

## 5단계 · 제출 지원 ✅ 🔧 ⬜

### ⬜ 반드시 들어가야 할 것 — 은행 순회 안내

조사에서 나온 가장 실용적인 발견들입니다.

**최초로 정지를 신청한 은행부터 확인하세요.** 여러 계좌가 묶였을 때 *"처음 정지를 요청한 은행이 풀어줘야 한다"*는 답을 듣게 됩니다. 한 사람은 농협 이의제기 → 신규계좌 개설 → 국민신문고·금감원 민원 → 국민·신한·농협·OK저축은행을 차례로 돌고 나서야 그 사실을 알았습니다.

**여러 계좌면 순차가 아니라 동시에 넣으세요.** 같은 자료·같은 사실관계인데 **은행에 따라 5일과 28일**로 5배까지 차이 납니다. 한 곳씩 기다리면 기한이 지나갑니다.

**창구에서 반려당하면 서면 답변을 요구하고 금감원 1332를 병행하세요.** 서류가 부족해서가 아니라 **접수 자체가 안 되는 단계**가 실제로 존재합니다. 대포통장 명의인 등록 해제를 신청했더니 *"이미 사기에 사용된 계좌라 재사용 불가, 대출금 다 갚고 해지하라"*며 반려한 사례가 있습니다.

**돈을 임의로 돌려주지 마세요.** 직접 반환은 자금세탁 가담 위험이 있습니다. **은행을 통해 반환하고 기록을 남기세요.**

### 🔧 "풀렸다"를 네 가지로 나눠 표시합니다

지금은 단일한 진행 상황으로 보여주는데, 하나로 뭉뚱그리면 **이용자를 잘못 안심시킵니다.**

| 상태 | 뜻 |
|---|---|
| 이의제기 접수됨 | 냈다 |
| **이의제기 수용됨** | 은행이 받아들였다. **아직 해제는 아니다** |
| 은행 지급정지 해제됨 | 그 은행 계좌가 풀렸다 |
| 금감원 전자금융거래제한 해제됨 | 전 금융권 제한이 풀렸다. **은행 해제와 열흘 넘게 차이 난다** |

그리고 **정지는 자동으로 번지는데 해제는 번지지 않습니다.** 1차 수취인이 풀려도 2차는 처음부터 다시 소명해야 합니다. 계좌별로 상태를 따로 표시해야 합니다.

### ⬜ 막혔을 때의 안내

> 이의제기가 반려되면 소송으로 다투기가 어렵습니다. 은행의 반려 통지는 **행정처분이 아니어서 항고소송이 각하**되고(2025구합56589), 채무부존재확인도 2026년 들어 하급심에서 대거 각하되고 있습니다.
>
> **그래서 첫 제출이 가장 중요합니다.** 반려되면 보완해서 다시 내고, 그래도 안 되면 금감원 민원으로 가세요.

## 4부 · 심사자 확인 절차 (첨부2 5번 원고)

배포 URL에 접속하면 **로그인 없이 바로 시작**합니다. 테스트 계정이 필요 없습니다.

### 정상 경로 — 약 3분

| 순서 | 무엇을 | 예상 결과 |
|---|---|---|
| 1 | 접속 → 안내 모달 "확인" | 랜딩 화면 |
| 2 | "시작하기" | 1단계 진단 시작 |
| 3 | 자유 서술에 **"당근에서 아이폰 팔았는데 어제 은행에서 계좌 정지됐다고 문자가 왔어요"** 입력 | **AI가 트랙(은행 길)·목적물(실물 중고물품)·구조(물건 넘김)를 판별하고, 확인 문항만 남깁니다** |
| 4 | 남은 문항에 답변 — 전달 방식 **택배**, 금액 **같았음**, 입금자명 **달랐음** | 트랙 판정 결과 화면 |

| 6 | 2단계 → **"샘플로 체험하기"** | 가상 거래내역·대화가 입력되고 완결성 게이지 상승 |
| 7 | 은행 선택 (예: 카카오뱅크) | **그 은행이 실제로 안내하는 요구서류가 표시됨** |
| 8 | 3단계 진입 | **AI가 사실관계를 뽑고 입금자명 불일치를 지적** |
| 9 | 4단계 진입 | **소명서 초안 3종 생성. 문장마다 출처 번호가 붙어 있음** |
| 10 | 5단계 진입 | 은행 순회 안내와 상태 표시 |

**4번에서 "달랐음"을 고른 것이 핵심입니다.** 그 불일치를 8번과 9번에서 어떻게 다루는지가 이 서비스의 대표 기능입니다.

### 경계 경로

|---|---|
| Q1에서 **"아직 연락은 없는데 이상한 게 보입니다"** | **경보 단계 화면** — "지금 당장 저장하세요" 목록 |
| Q1에서 **"경찰에서 조사받으러 오라고"** | **경찰 길 화면** — 이의제기가 아니라 진술서 안내 |

### 오류 경로

- 2단계에서 아무것도 안 올리고 다음 → **필수 항목이 비었다는 안내**, 진행 안 됨
- 형식이 맞지 않는 CSV 업로드 → 오류 메시지, 화면 안 깨짐
- LLM 응답 지연 → 로딩 표시 후 재시도 안내, 화면 안 깨짐

### 실행 환경

- 최신 Chrome · Safari · Edge
- **모바일 반응형** — 계좌 정지 문자를 받은 자리에서 휴대폰으로 쓰는 상황을 전제
- 로그인·회원가입 없음

### MVP 단계의 한계 (반드시 함께 밝힐 것)

- **화면의 거래내역과 대화는 가상 데이터**입니다. 실제 피해자 자료가 아닙니다
- **이미지 OCR 결과는 사람이 확인해야 합니다.** 캡처 화질에 따라 금액·날짜가 잘못 읽힐 수 있어, 추출값을 화면에 띄우고 수정받은 뒤에 씁니다
- **은행에 실제로 제출하는 기능은 없습니다.** 문서 생성과 제출 안내까지입니다
- AI 초안은 **제안**이며, 최종 판단은 은행과 금융감독원이 합니다
