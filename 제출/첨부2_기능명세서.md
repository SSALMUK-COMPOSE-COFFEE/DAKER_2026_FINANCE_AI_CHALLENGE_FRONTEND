## 1. MVP 구현 범위

 ※ 아래 「포함한 것」은 **9/6 시점에 실제 동작하는 항목만 남길 것**. 현재는 개발 목표 기준으로 기재돼 있음.

1. 구현 범위에 포함한 것
  o **상황 진단** : 자유 서술 입력을 AI가 분류하고, 확인 문항으로 트랙·유형·적용 조항을 확정함
  o **절차 안내** : 판정된 트랙에 따라 은행 이의제기·경찰 진술서·증거 선제 보존 중 맞는 경로를 제시함
  o **기한 산정** : 채권소멸절차 개시 공고일을 기준으로 잔여 기한을 계산하고, 공고 전에는 별도 안내로 대체함
  o **증거 준비** : 유형별 증거 체크리스트와 거래은행이 실제로 요구하는 서류를 제시하고, 완결성을 표시함
  o **발급 요청문 생성** : 게임사·발행사·구청 등 증거 발급처에 보낼 요청문 초안을 생성함
  o **캡처 이미지 판독** : 대화 캡처·거래내역 캡처·지급정지 문자 캡처를 **생성형 AI의 이미지 입력**으로 직접 읽어 사실관계를 추출함. 별도 OCR 엔진을 두지 않고 분류·분석 호출에 이미지를 함께 전달함. 텍스트 붙여넣기와 CSV 업로드도 병행 지원함
  o **AI 분석** : 거래 대화와 거래내역에서 사실관계를 추출하고, 입금자명 불일치와 금액 정합성을 점검함
  o **소명서 생성** : 이의제기신청서 사유란·경위서·증거 인덱스 3종을 생성하며, 전 문장에 출처를 표기함. **통장협박·통장묶기 유형의 소명서도 포함함**
  o **제출 지원** : 은행별 제출 경로와 진행 상태를 안내함

2. 구현 범위에서 제외한 것
  o **은행 실제 제출** : 문서 생성과 제출 안내까지이며, 전자 접수 연동은 포함하지 않음
  o **로그인·회원가입** : 자료를 저장하지 않는 설계이므로 계정 체계를 두지 않음
  o **계좌 관계망 판정 모델** : 검증 가능한 데이터가 부재하여 채택하지 않음

## 3. 사용자 이용 흐름

1. 진입
  o 배포 URL 접속 시 **로그인 없이 즉시 시작**함
  o 고지 모달에서 서비스의 한계를 확인하고 동의함

2. 상황 진단
  o 겪은 일을 자유롭게 서술함. 건너뛰고 문항부터 답해도 무방함
  o AI가 서술문을 분류하고, 확신도가 낮은 항목만 확인 문항으로 되물음
  o 위험 신호가 감지되면 이 지점에서 안내 후 종료함

3. 트랙 판정 결과 확인
  o 은행 길·경찰 길·경보 단계 중 해당 경로와 그 근거를 확인함
  o 은행 길인 경우 기한 안내와 금액 입력으로 이어짐

4. 증거 준비
  o 유형별 체크리스트와 거래은행의 요구서류를 확인함
  o 보유하지 않은 자료는 발급 요청문 초안을 복사하여 발급처에 요청함
  o 대화 텍스트와 거래내역 CSV를 입력하고 완결성을 확인함

5. AI 분석 확인
  o 추출된 사실관계, 입금자명 불일치, 금액 정합성, 계좌 정상성 근거를 확인함

6. 소명서 초안 작성
  o 생성된 3종 문서를 확인하고 직접 수정하거나 재작성을 요청함
  o 사실과 다른 부분을 이용자가 최종 확인함

7. 제출
  o 은행별 제출 경로 안내에 따라 접수하고, 진행 상태를 기록함

## 4. AI 및 데이터 처리 방식

1. AI가 수행하는 역할 (3계층)

 1-1. 1층 · 분류
  o 입력 : 자유 서술문, 기존 문항 답변
  o 처리 : 트랙(은행·경찰·경보·민사), 구조, 목적물, 적용 조항(법 제7조제1항 각 호), 범위 밖 신호를 판별함
  o 출력 : 판별 결과와 항목별 확신도. 확신도 미달 항목만 추가 질문으로 반환함
  o 특성 : 발굴 유형이 19종이고 당사자가 자기 유형을 인지하지 못하므로, 객관식만으로는 분류가 불가능함

 1-2. 2층 · 검색 (RAG)
  o 입력 : 1층의 판별 결과, 거래은행명
  o 처리 : 자체 구축 코퍼스에서 근거를 인출함
   - 은행 이의제기 요구서류(금융회사 20곳)
   - 판결문 원문 18건 및 판례 33건
   - 금융감독원 보도자료 49건 및 첨부 PDF 32건
   - 통신사기피해환급법 및 시행령 원문
   - 정리 피해사례 233건
  o 출력 : 근거 문단과 출처 식별자. 3층의 인용 범위를 이 결과로 한정함

 1-3. 3층 · 생성
  o 입력 : 1층 사실관계, 2층 근거, 이용자 제공 증거
  o 처리 : 법정서식의 「이의제기 사유」 3항목 구조(① 입금 금액·시간 ② 입금 경위 ③ 권원 주장과 증빙)에 맞추어 문장을 생성함
  o 출력 : 이의제기신청서 사유란·경위서·증거 인덱스
  o 제약 : **2층이 인출한 근거의 범위 내에서만 생성**하며, 근거가 없는 문장은 생성하지 않음. 전 문장에 출처를 표기함

2. 사용 데이터

 2-1. 자체 구축 코퍼스 (총 877건 · 본문 150만 자)
  o 법률매체 상담사례 573건, 당사자 게시글 222건, 금감원 보도자료 49건 및 PDF 32건
  o 판례 33건, 판결문 원문 18건, 정리 피해사례 233건, 은행 안내 실측 20곳
  o 수집 시 주민번호·계좌번호·전화번호를 파일 기록 이전에 마스킹하였으며, robots.txt를 준수함

 2-2. 공개 자료
  o 통신사기피해환급법 및 시행령 원문, 별지 제4호서식, 금감원 공통 소명자료 기준, 은행별 작성예시

 2-3. 시연용 합성 데이터
  o 실제 피해자 데이터를 사용하지 않으며, 화면에 "가상 데이터"로 표기함

3. 입력·출력 데이터

| 구분 | 입력 | 출력 |
|---|---|---|
| 상황 진단 | 자유 서술문, 문항 답변 | 트랙·구조·목적물·적용 조항, 추가 질문 |
| 증거 준비 | 유형, 거래은행명 | 증거 체크리스트, 은행별 요구서류, 발급 요청문 |
| AI 분석 | 거래 대화 텍스트, 거래내역 CSV | 사실관계 표, 입금자명 불일치, 금액 정합성, 계좌 정상성 지표 |
| 소명서 생성 | 위 결과 전체 | 사유란·경위서·증거 인덱스, 출처 목록 |

4. 개인정보 및 민감정보 처리
  o **저장하지 않음** : 이용자가 제공한 자료는 서버에 저장하지 않고 세션 내에서만 처리한 뒤 파기함
  o **자동 마스킹** : 제3자의 성명·연락처·계좌번호를 처리 이전에 마스킹하며, 마스킹된 형태로만 모델에 전달함
  o **계정 미보유** : 로그인과 회원가입이 없어 이용자를 식별하지 않음
  o **고지 시점** : 접속 직후 모달에서 위 사항을 고지하고 동의를 받음

## 5. MVP 검증 방법

1. 접속 조건
  o 배포 URL 접속만으로 즉시 이용 가능하며, **테스트 계정이 필요하지 않음**
  o 최초 진입 시 고지 모달에서 "확인"을 선택함

 ※ 아래 절차는 **AI 연동 완료(T-05·T-08)를 전제로 작성됨.** 9/6 시점에 미완이면
 3·6·7·8·9번을 실제 동작하는 조작으로 교체해야 함. 심사자가 따라 하다 막히면
 URL 미동작과 동일하게 취급될 수 있음.

2. 정상 경로 검증 (소요 약 3분)

| 순서 | 조작 | 예상 결과 |
|---|---|---|
| 1 | 접속 후 고지 모달에서 "확인" | 랜딩 화면이 표시됨 |
| 2 | "시작하기" 선택 | 진단 1단계로 진입함 |
| 3 | 자유 서술란에 **"당근에서 아이폰 팔았는데 어제 은행에서 계좌 정지됐다고 문자가 왔어요"** 입력 | 트랙은 은행 길, 목적물은 실물 중고물품, 구조는 물건 넘김으로 판별되고, 남은 문항만 제시됨 |
| 4 | 전달 방식 **택배**, 금액 **같았음**, 입금자명 **달랐음** 선택 | 트랙 판정 결과 화면이 표시됨 |
| 5 | 기한 안내 확인 | 공고 통지 미수령이므로 "마감일 미확정, 지금 바로 접수 가능"으로 안내됨 |
| 6 | 증거 준비에서 **"샘플로 체험하기"** 선택 | 가상 거래내역과 대화가 입력되고 완결성 게이지가 상승함 |
| 7 | 거래은행으로 **카카오뱅크** 선택 | 해당 은행이 실제로 안내하는 요구서류가 표시됨 |
| 8 | AI 분석 화면 진입 | 사실관계가 추출되고 **입금자명 불일치**가 지적됨 |
| 9 | 소명서 초안 화면 진입 | 3종 문서가 생성되고 문장마다 출처 번호가 표시됨 |
| 10 | 제출 지원 화면 진입 | 은행별 제출 경로와 4단계 진행 상태가 표시됨 |

 ※ 4번에서 입금자명을 "달랐음"으로 선택하는 것이 핵심임. 해당 불일치를 8번과 9번에서 어떻게 다루는지가 본 서비스의 대표 기능임

3. 경계 경로 검증

| 입력 | 예상 결과 |
|---|---|
| Q1에서 "아직 연락은 없는데 이상한 게 보입니다" | 경보 단계 화면과 즉시 보존할 자료 목록이 표시됨 |
| Q1에서 "경찰에서 조사받으러 오라고 연락이 왔습니다" | 경찰 길 화면이 표시되며, 이의제기가 아니라 진술서를 안내함 |
| Q3에서 "환전받은 돈입니다" | 리스크 게이트가 작동하여 문서 생성을 중단하고 전문기관을 안내함 |
| Q6에서 "더 들어왔습니다" | 임의 반환 금지 경고와 은행 반환 절차 안내가 즉시 표시됨 |
| Q8에서 "통장·카드를 남에게 넘김" | 서비스 대상에서 제외하고 법률구조공단(132)을 안내함 |

4. 오류 경로 검증
  o 필수 항목을 비운 채 다음 단계를 시도하면 진행이 차단되고 미입력 항목이 표시됨
  o 형식이 맞지 않는 CSV를 업로드하면 오류 메시지가 표시되고 화면이 정상 유지됨
  o AI 응답이 지연되면 로딩 상태가 표시되고, 실패 시 재시도 안내가 표시됨

5. 실행 환경
  o 최신 Chrome, Safari, Edge에서 동작함
  o **모바일 반응형**으로 구현함. 지급정지 통보를 받은 자리에서 휴대폰으로 이용하는 상황을 전제함
  o 로그인·회원가입·앱 설치가 필요하지 않음

6. MVP 단계의 제한사항
  o 화면에 표시되는 거래내역과 대화는 **가상 데이터**이며 실제 피해자 자료가 아님
  o **은행에 실제로 제출하는 기능이 없음**. 문서 생성과 제출 안내까지임
  o AI가 생성한 초안은 **제안**이며, 최종 판단은 은행과 금융감독원이 함
